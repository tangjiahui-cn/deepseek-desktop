# Spec Delta

## Purpose

让桌面应用发现新版本时以不打扰的方式提示，并且只在用户明确同意后下载和安装更新，同时保证退出、取消和安装中断时不会留下半装状态或数据损坏。

## ADDED Requirements

### Requirement: 更新检查

打包后的应用 SHALL 在界面可用后自动检查一次更新，并允许用户从菜单手动检查；未打包的开发模式不得发起更新检查。

#### Scenario: 启动后自动检查
- **WHEN** 已安装的应用启动并完成界面加载
- **THEN** 应用在后台检查更新，不阻塞聊天界面

#### Scenario: 手动检查
- **WHEN** 用户从菜单选择「检查更新」
- **THEN** 应用立即检查，并在无更新时给出明确反馈

#### Scenario: 开发模式
- **WHEN** 以未打包的开发模式运行
- **THEN** 应用不发起任何更新检查请求

### Requirement: 可关闭的新版本提示

发现更高的稳定版本时，应用 SHALL 在应用内显示包含版本号与更新操作的提示标签；用户关闭后，该版本在本机不再提示，直到出现更高版本或用户手动检查。

#### Scenario: 显示更新提示
- **WHEN** 检查发现更高的稳定版本
- **THEN** 应用内出现带版本号和更新操作的提示标签，聊天界面照常可用

#### Scenario: 关闭提示
- **WHEN** 用户关闭该标签
- **THEN** 当前会话内不再显示该提示，重启应用后同一版本也不再显示

#### Scenario: 出现更高版本
- **WHEN** 用户关闭过 vX.Y.Z 的提示，之后发现更高的版本
- **THEN** 应用重新显示更新提示

#### Scenario: 手动检查重新提示
- **WHEN** 用户对已关闭提示的版本执行手动检查
- **THEN** 提示重新出现

### Requirement: 显式下载

应用 SHALL NOT 在用户确认前下载更新包；用户选择更新后 SHALL 显示下载进度并允许取消，取消后不得保留可安装的半成品。

#### Scenario: 未确认不下载
- **WHEN** 应用发现新版本但用户尚未选择更新
- **THEN** 应用只完成版本检查，不下载更新包

#### Scenario: 显示下载进度
- **WHEN** 用户选择更新并开始下载
- **THEN** 提示标签显示下载进度，用户可以继续使用聊天界面

#### Scenario: 取消下载
- **WHEN** 用户在下载过程中取消
- **THEN** 下载停止，半成品被清理，不进入可安装状态

#### Scenario: 下载完成
- **WHEN** 下载完成
- **THEN** 提示标签变为「重启并安装」，应用不会自行安装

### Requirement: 显式安装

应用 SHALL 只在用户明确选择安装后执行安装，并在安装前停止正在生成的回复与朗读、等待本地数据持久化；若正在生成回复，必须先向用户确认。

#### Scenario: 确认安装
- **WHEN** 用户点击「重启并安装」
- **THEN** 应用完成收尾后退出并安装，下次启动运行新版本

#### Scenario: 流式回复中安装
- **WHEN** 用户在有回复正在生成时选择安装
- **THEN** 应用提示安装会中断当前回复，用户确认后才继续

#### Scenario: 取消安装
- **WHEN** 用户在安装前的确认中取消
- **THEN** 不安装，应用继续运行当前版本

### Requirement: 按平台提供更新动作

Windows 与 Linux AppImage SHALL 在应用内下载并安装；macOS 与 Linux deb SHALL 只提供打开发布页面的入口，不得在应用内下载或安装。

#### Scenario: Windows 与 AppImage
- **WHEN** 用户在 Windows 或 AppImage 版本中选择更新
- **THEN** 应用内完成下载与安装

#### Scenario: macOS
- **WHEN** 用户在 macOS 上选择更新
- **THEN** 默认浏览器打开对应版本的发布页面，应用不下载安装包

#### Scenario: Linux deb
- **WHEN** 用户在 deb 版本中选择更新
- **THEN** 默认浏览器打开对应版本的发布页面，不弹出系统权限或包管理器窗口

### Requirement: 退出与中断处理

下载中退出 SHALL 取消下载且不安装；已下载但未安装时退出，应用 SHALL 询问「安装并退出」或「直接退出」；安装进行中再次启动应用 SHALL 被阻止并提示安装尚未完成。

#### Scenario: 下载中退出
- **WHEN** 用户在下载过程中退出应用
- **THEN** 下载被取消，不安装，也不留下可安装的半成品

#### Scenario: 已下载时退出
- **WHEN** 用户在更新已下载但未安装时退出应用
- **THEN** 应用弹窗询问「安装并退出」或「直接退出」，选择直接退出则不安装

#### Scenario: 安装中重新启动
- **WHEN** 安装程序仍在运行时用户再次启动应用
- **THEN** 应用提示更新正在安装并退出，不与安装程序同时运行

#### Scenario: 安装被中断
- **WHEN** 安装程序被强制终止且版本未变化
- **THEN** 下次启动提示上次更新未完成，并允许重新下载安装

### Requirement: 只接受更高的稳定版本

应用 SHALL 只在已发布（非 draft、非预发布）的 Release 中查找更新，并且仅当远端版本高于当前版本时才提示或安装。

#### Scenario: 远端版本更旧
- **WHEN** 远端最新版本低于或等于当前版本
- **THEN** 应用不显示更新提示

#### Scenario: 预发布版本
- **WHEN** 远端最新 Release 被标记为预发布
- **THEN** 应用忽略该版本

### Requirement: 更新失败不影响使用

更新检查、下载或安装失败时，应用 SHALL 继续以当前版本运行，以非阻塞方式提示失败，并且不得影响本地会话与设置。

#### Scenario: 检查失败
- **WHEN** 检查更新时网络不可用
- **THEN** 应用保持可用，只在用户主动检查时提示失败

#### Scenario: 下载失败
- **WHEN** 下载过程中断网或校验失败
- **THEN** 提示可重试，当前版本继续可用，不留半成品

#### Scenario: 安装失败
- **WHEN** 新版本安装失败
- **THEN** 当前版本或重装后的版本可继续使用，用户数据保持完整，并提示可手动前往发布页面
