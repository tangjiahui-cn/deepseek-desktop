# Proposal

## Why

当前对话之间互不记忆：用户在上一段对话里说明的项目、偏好和长期约束，到新对话里必须重新说一遍。自定义提示词只能手动维护，无法从对话中积累；逐条记忆又需要用户管理、合并和清理。需要一份默认关闭、自动更新、用户可见可改的跨对话长期画像。

## What Changes

- 记忆改为**一段长期画像**：合并用户身份/环境、偏好、项目/目标、约束，作为唯一注入源；不再保存逐条记忆。
- 每轮回复结束后 **30 秒防抖**更新画像；新提问或新回复会重置计时；新建对话/切换会话立即更新；连续长对话达到 50 条/12000 字时立即处理作为兜底。
- 只处理开启记忆之后产生的新消息，按会话 checkpoint 增量读取；启动时补跑未处理的会话，不回填开启前的历史。
- 画像软目标约 1200 字，硬上限 2000 字；超过时先压缩一次，压缩后仍超限则暂停自动更新并提示用户精简。
- 画像更新由 `deepseek-flash` 完成：输入当前画像 + 新对话，输出更新后的完整画像；保留未被推翻的旧事实，合并/更新冲突内容。
- 用户可手动编辑画像；编辑后自动更新暂停，提供“恢复自动更新”和“撤销上次更新”。清空画像保留 checkpoint，避免已处理对话重新生成。
- 设置新增「记忆」tab：总开关（默认关闭）、画像编辑框、字数计数、最近更新来源、撤销、清空。
- 画像只保存在本机 localStorage；不进入现有历史导出/导入，也不改动 IndexedDB 与会话格式。
- 非目标：逐条记忆条目、按问题检索、会话级“不记住”、自动补跑旧历史、跨设备同步、画像导出。
- **BREAKING**：无。默认关闭时现有请求与数据格式完全不变。

## Capabilities

### New Capabilities

- `memory`: 跨对话长期记忆画像。负责什么内容可以成为画像、30 秒防抖的增量更新、画像长度与压缩、用户编辑/撤销、在请求中的注入，以及默认关闭和本机存储边界。

### Modified Capabilities

无。`personalization` 的自定义提示词行为不变；画像只是在其之后追加一段独立内容。

## Impact

- **新增代码**：画像存储、30 秒调度、画像提取与压缩、画像编辑/撤销界面、注入拼装、中英文文案。
- **修改代码**：`src/services/memory/`（替代条目模型）、`src/services/chat/store.ts`（新提问重置计时、回复后调度、注入）、`src/services/chat/systemPrompt.ts`（组合画像）、`src/components/settings/`（记忆分组）、`src/i18n/`。
- **API**：每轮空闲后额外一次 `deepseek-flash` 画像请求；超限时可能多一次压缩请求。不改变现有消息协议、会话数据或历史归档格式。
- **数据迁移**：旧版本地条目会在首次读取时拼接成一段画像并删除旧 key；当前功能尚未发布，无线上迁移压力。
- **隐私**：画像会随每次生成请求发送；默认关闭、可编辑、可清空；不进入历史导出包。
- **范围外**：逐条来源、检索、会话级豁免、旧历史回填、自动删除、敏感信息强过滤。
