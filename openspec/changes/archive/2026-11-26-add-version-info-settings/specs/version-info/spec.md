# Spec Delta

## Purpose

在设置中展示应用版本、运行平台与桌面运行时版本，并在进入分组时自动查询一次新版本，复用现有桌面更新流程，让用户不必寻找系统菜单。

## ADDED Requirements

### Requirement: 版本信息分组

设置 SHALL 在左侧分组末尾提供「版本信息」分组，展示应用版本与运行平台；桌面端 SHALL 额外展示 Electron、Chromium、Node 版本。版本信息不可获取时 SHALL 显示「未知」而不是空白。

#### Scenario: 桌面端版本信息
- **WHEN** 用户在桌面端打开设置并选择「版本信息」
- **THEN** 分组显示应用版本、平台（macOS / Windows / Linux）以及 Electron、Chromium、Node 版本

#### Scenario: Web 版版本信息
- **WHEN** 用户在 Web 版打开「版本信息」
- **THEN** 分组显示应用版本与平台「Web」，不显示桌面运行时版本

#### Scenario: 分组位置
- **WHEN** 用户打开设置
- **THEN** 「版本信息」显示在「数据管理」之后，是最后一个分组

#### Scenario: 版本不可用
- **WHEN** 构建期版本或桌面桥接信息缺失
- **THEN** 对应项显示「未知」，其余信息与设置仍可正常使用

### Requirement: 进入分组时自动查询

桌面端每次进入「版本信息」分组时 SHALL 自动查询一次新版本，停留在分组内不得重复查询；查询期间 SHALL 显示查询中状态并禁用按钮。查询完成后无更新 SHALL 显示「已是最新版本」，有更新 SHALL 显示「发现新版本 vX」；查询失败 SHALL 显示失败状态并允许刷新。开发模式沿用现有不发起检查的行为。

#### Scenario: 进入分组且无更新
- **WHEN** 用户进入「版本信息」分组且当前已是最新版本
- **THEN** 分组显示查询中，随后显示「已是最新版本」

#### Scenario: 进入分组发现有更新
- **WHEN** 用户进入「版本信息」分组且远端有更高版本
- **THEN** 分组显示查询中，随后显示「发现新版本 vX」

#### Scenario: 停留在分组内
- **WHEN** 用户停留在「版本信息」分组且不点击刷新
- **THEN** 不重复发起查询

#### Scenario: 重新进入分组
- **WHEN** 用户离开「版本信息」后再次进入
- **THEN** 重新自动查询一次

#### Scenario: 查询失败
- **WHEN** 查询因网络或服务错误失败
- **THEN** 分组显示失败状态，按钮回到「刷新」，应用继续可用

#### Scenario: 开发模式
- **WHEN** 未打包的开发模式进入「版本信息」分组
- **THEN** 不发起更新查询请求，沿用现有开发模式提示

### Requirement: 三态更新按钮

版本信息分组 SHALL 只提供一个更新按钮，且仅呈现三种状态：「刷新」（默认、已是最新、失败）、「查询中」（查询进行中，loading，禁用）、「更新」（发现新版本）。点击「刷新」SHALL 重新查询，点击「更新」SHALL 执行对应平台的更新动作，按钮不得出现第四种文案。

#### Scenario: 默认状态
- **WHEN** 分组尚未发现新版本
- **THEN** 按钮显示「刷新」

#### Scenario: 查询进行中
- **WHEN** 自动查询或点击刷新后的查询正在进行
- **THEN** 按钮显示「查询中」并处于禁用状态

#### Scenario: 发现新版本
- **WHEN** 查询发现更高的远端版本
- **THEN** 按钮显示「更新」

#### Scenario: 失败后恢复
- **WHEN** 查询失败
- **THEN** 按钮回到「刷新」，点击可再次查询

### Requirement: 发现新版本时更新

发现新版本时，分组 SHALL 显示远端版本号；支持应用内下载的平台点击「更新」后 SHALL 开始下载，其他平台 SHALL 打开发布页。下载中与已下载状态 SHALL 以状态文字展示，按钮保持「更新」并禁用；安装 SHALL 由现有侧栏更新提示承接，分组不得自行安装。

#### Scenario: 支持应用内更新
- **WHEN** Windows 或 Linux AppImage 版本发现新版本
- **THEN** 分组显示新版本号和「更新」按钮，点击后开始下载，并提示可在侧栏查看进度

#### Scenario: 仅支持打开发布页
- **WHEN** macOS 或 Linux deb 版本发现新版本
- **THEN** 分组显示新版本号和「更新」按钮，点击后由系统浏览器打开发布页

#### Scenario: 下载中
- **WHEN** 应用内下载正在进行
- **THEN** 分组显示下载进度文字，按钮保持「更新」并禁用

#### Scenario: 更新已下载
- **WHEN** 更新包已下载但尚未安装
- **THEN** 分组显示已下载状态并提示在侧栏完成安装，分组内不提供直接安装

### Requirement: Web 版禁用检查

Web 版版本信息分组 SHALL 显示禁用的「刷新」按钮，并说明自动更新仅桌面版可用；Web 版不得发起更新查询请求。

#### Scenario: Web 版按钮
- **WHEN** 用户在 Web 版打开「版本信息」
- **THEN** 「刷新」按钮为禁用状态，并显示仅桌面版支持的说明

#### Scenario: Web 版不发起请求
- **WHEN** 用户在 Web 版尝试触发查询
- **THEN** 不发起任何更新查询请求

### Requirement: 不改变现有更新策略

进入分组的自动查询 SHALL 复用现有检查流程并视为一次手动检查；已有下载中、已下载或安装中的更新时 SHALL 直接展示当前状态、不发起新的查询。分组不得新增后台轮询、自动下载或自动安装，也不得改变现有的下载确认与安装确认。

#### Scenario: 已有下载中的更新
- **WHEN** 用户进入「版本信息」分组时更新正在下载或已下载
- **THEN** 分组直接展示当前下载或已下载状态，不发起新的查询

#### Scenario: 下载与安装确认
- **WHEN** 用户从版本信息开始下载或安装
- **THEN** 仍遵循现有的下载确认、安装确认与中断处理
