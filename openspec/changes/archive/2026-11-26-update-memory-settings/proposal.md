# Proposal

## Why

当前记忆能力把“记什么”和“能记多长”都写死在代码里：固定四类内容、软目标 1200 字、硬上限 2000 字；一旦超限或用户编辑过画像，就暂停自动更新，必须点“恢复自动更新”或手动精简才能继续。用户需要自己决定记忆的边界和容量，并且希望记忆像一份持续维护的档案一样自动合并、自动收敛，而不是频繁回到设置里手动干预。

## What Changes

- 新增「最大记忆长度」设置：2000–20000 字，默认 **7000**；画像写入、注入和编辑都受该值约束。
- 新增可编辑的「记忆要求」：默认六类（身份与角色、环境与工具链、长期偏好、项目与目标、约束与禁忌、已确认的事实修正），用户可改写；提取模型按当前记忆要求判断哪些内容可写入画像。
- 当前记忆改为**每次自动合并**：提取结果以“当前记忆 + 新对话”为输入，按记忆要求合并，长度超过上限时优先丢弃优先级低的旧事实、保留新事实；**「约束与禁忌」永不自动删除**，其余按固定顺序淘汰。
- 自动更新不再因超限或用户编辑而暂停：超限时自动压缩，压缩仍失败则保留旧记忆并在后续触发时重试，不需要用户手动恢复。
- 移除「撤销上次更新」与旧版本栈；当前记忆的编辑统一为**编辑 / 保存 / 取消**：保存后的内容成为后续合并的基线，自动更新继续；编辑期间不覆盖用户正在输入的内容。
- 设置的「记忆」分组增加最大长度输入、记忆要求编辑框与当前记忆编辑框；字数统计以配置的最大长度为准。
- 设置与记忆要求保存在本机 localStorage；旧画像中的撤销版本、`userEdited`、`overflow` 字段在读取时兼容并忽略，不阻塞升级。
- 非目标：逐条记忆条目、按问题检索、跨设备同步、画像导出、恢复历史版本。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `memory`: 记忆内容来源改为可配置的「记忆要求」；长度上限可配置（2000–20000，默认 7000）；更新策略改为每次自动合并并按优先级淘汰旧内容；用户编辑不再暂停自动更新，移除撤销；超限不再暂停等待手动处理。

## Impact

- **修改代码**：`src/services/settings.ts`（新增最大长度与记忆要求）、`src/services/memory/`（类型、存储迁移、注入、提取与压缩提示词、调度）、`src/components/settings/MemoryField.tsx` 与 `Settings.module.css`（新增设置项、移除撤销/恢复）、`src/i18n/zh.ts`、`src/i18n/en.ts`；`README.md` 与 `README.en.md` 同步说明。
- **API**：不变。提取/压缩仍使用 `deepseek-flash`、严格 JSON；仅提示词与长度校验改为读取设置。
- **数据迁移**：旧画像的 `revisions`、`userEdited`、`overflow` 读取时忽略并清理；画像正文、更新来源、checkpoint 保留。
- **隐私与边界**：画像仍只存本机、随请求发送、不进入历史导出；记忆要求本身不发送给聊天请求，只用于整理画像。
